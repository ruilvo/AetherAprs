# R6.6 audit: what landed, what did not

Date: 2026-11-27. Baseline commit `71b3e29` (merge of the R6.6 transport work).

This document records an audit of the R6.6 roadmap row against the shipped code, and
of two cross-cutting questions raised at the same time (callsign versus addressee, and
use of `Stateless` for state machines). It exists so a later session can act on the
findings without repeating the investigation.

The audit's verdict: **R6.6 was reported complete and is not.** Six clauses of the row
are unimplemented or unreachable. Three of them were missed because the unit tests
build their own inputs instead of driving the real producers.

---

## 1. How the gap was missed

`AetherAprs.Tests/Android/AudioTransmitGateTests.cs` and
`AetherAprs.Tests/Android/AudioWriteLoopTests.cs` pass 30 green tests by
hand-constructing `AudioRouteSnapshot` values. They verify the gate's *logic* in
isolation. Nothing in the product ever constructs a snapshot or assigns it to
`AudioPlaybackService.RouteSnapshot`, so the gate is a permanent pass-through in the
shipped application.

The earlier conclusion "every acceptance bullet is covered by named tests" came from
reading test names rather than tracing call sites. **When auditing a row like this,
grep for the production writer of each input the tests fabricate.** A test that builds
its own input proves the consumer works, never that anything delivers that input.

## 3. Confirmed gaps — work items

The roadmap carried these as R6.9 to R6.11; all three are now resolved and the
roadmap keeps only R6.6's device check. Each section below records what closed it.

### 3.1 R6.9 — AFSK port editor (resolved)

**Resolved.** `AfskSettings` is now a first-class port type in the editor:

- `AddEditPortViewModel.PortTypes` offers `typeof(AfskSettings)`; `Initialize` and
  `BuildConfig` populate and write `PttMode`, `TxDelayMs`, `TxTailMs`, `SlotTimeMs`
  and `Persist`; the page gains an AFSK section gated on `AfskSettings`.
- `EnumDisplayConverter` maps `AfskSettings` ↔ `PortTypeAfsk` in both directions, and
  `PortItemViewModel.TypeName` renders `AFSK` instead of `PortTypeUnknown`.
- `IPttService.SupportsPhysicalPtt` separated the capability question from the mode:
  `PttMode.None` was renamed to `PttMode.Vox` (same stored value `0`), and the editor
  offers `SpeakerMic` only when the platform can key the transmitter. A stored mode the
  platform cannot perform stays selected so it round-trips instead of being rewritten.
- `AudioLevel` and `SquelchThreshold` were removed outright. Neither was a real control:
  transmit loudness is the phone's own volume, and the demodulator never read the
  squelch value (`AfskDemodulator` has no amplitude gate; the HDLC FCS discards noise).
  A migration drops both columns.
- Covered by editor round-trip tests (create/edit/reload), converter tests both
  directions, `TypeName`, mapper round-trip, and validation rejections for negative
  timings and out-of-range persist.

### 3.2 R6.10 — audio route and focus wiring

Resolved. The snapshot now has a production writer and the transmit path is checked
at every step:

- `AetherAprs/Services/Platform/AudioRoute.cs` owns `AudioRouteKind`,
  `AudioRouteSnapshot`, `AudioTransmitBlockReason`, `AudioRouteMonitor` (the producer:
  it advances the generation on route changes and noisy transitions and records focus
  separately) and `AudioRouteClassifier` (sink priority). `AudioTransmitGate`,
  `AudioRouteValidator` and `AudioRouteBlockedException` moved from the Android
  project to `AetherAprs/Services/Platform/AudioTransmitGate.cs`, so the core modem
  and the platform adapter share one gate instead of each keeping its own.
- `AetherAprs.Android/Services/Platform/AudioRoutePlatformSource.cs` is the platform
  source: it registers an `AudioDeviceCallback`, a receiver for
  `AudioManager.ActionAudioBecomingNoisy`, and a focus listener, requests transient
  focus from an `AudioFocusRequestClass` for the transmit duration, and feeds every
  observation into the shared `AudioRouteMonitor`. It is registered as a singleton in
  `Application.RegisterPlatformServices`; `AudioRouteMonitor` and `AudioTransmitGate`
  are singletons in `ServiceProviderFactory`.
- `IPttService.TryEngage()` acquires focus and keys through the gate, so
  `AfskModem.SendAsync` no longer calls the unconditional `Engage()`: a refused key
  throws `AudioRouteBlockedException` before any audio is played. `AudioPlaybackService`
  authorizes the live snapshot (owning focus for a VOX burst) and revalidates it before
  every chunk through the shared gate, and the settable `RouteSnapshot` property that
  nobody assigned is gone.
- Tests: `AetherAprs.Tests/Services/Platform/AudioRouteMonitorTests.cs` drives the real
  producer (route change, becoming-noisy mid-frame, focus loss, reset) and feeds the
  produced snapshots into the gate; `AfskModemTests` covers the refused-key path.
  What is left is the R6.6 device check (an actual headset unplugged mid-frame).

### 3.3 R6.11 — connection reporting gaps

Resolved: the negotiated service/characteristic UUIDs are rendered by
`KissConnectionStatusText.DescribeDetail`, `PortSessionManager` reports a one-based
attempt number to the connector (and resets it on a successful connect or an operator
stop), and the port list projects `PortSessionStatus` into `PortItemViewModel` so a
connected port, a connecting port and one waiting in backoff read differently.

Note for future rows: the original defect was found because three unit tests built
their own inputs instead of driving the real producer. Keep the regression tests tied
to the production path.

## 4. Callsign versus addressee — verdict: the model is right, one call site is wrong

The separation is deliberate, documented and correctly typed:

- `Models/Aprs/Callsign.cs` — strict AX.25 station identity: 2-6 ASCII alphanumerics
  plus optional SSID 0-15. Also carries `HasBeenRepeated` for path entries.
- `Models/Aprs/AprsAddress.cs` — APRS message addressee: 1-9 characters including
  hyphens, because the APRS message field is nine arbitrary characters and tactical
  addresses such as `APRS2SOTA`, `EMAIL` and `NWS-` are valid recipients.

Usage honours the distinction:

- station fields (`Source`, `Destination`) are `Callsign` throughout
  `Models/Aprs/Packets/`
- message destination is `AprsAddress` — `MessagePacket.Addressee`,
  `MessageAckPacket.Addressee`, `MessageRejPacket.Addressee`, all three
- `ConversationThread.Peer`, `MessageService` peers, `BroadcastFailedException` paths
  and `ConversationDeepLink` all use `AprsAddress`, and `ConversationDeepLink` carries
  an explicit comment explaining why a `Callsign` would be wrong there
- the arrow back to a station identity
  (`AprsAddress.TryToCallsign`) exists and is used only where AX.25 genuinely requires
  it

**The one defect was `MessageService.cs:1141`**: it converted a stored source through
`Callsign` instead of `AprsAddress.FromStored`, which forced addressee-shaped data
through the stricter station type and split a conversation after a restart when the
peer had no SSID. That path now uses `AprsAddress.FromStored`, like the addressee path
next to it, and a reload test asserts one thread per SSID-less peer.

No other misuse was found. Do not "unify" the two types — the split is load-bearing.

## 5. Stateless for state machines — verdict: correctly applied

`Stateless` 5.21.0 is referenced once (`Directory.Packages.props`,
`AetherAprs/AetherAprs.csproj`) and used by exactly three types, matching the roadmap's
declared list:

| Type | States | Shape |
|---|---|---|
| `Models/Messaging/MessageDelivery.cs` | `Queued → Pending → Sending →` terminal | `Fire` / `TryFire` / `CanFire`, terminal states configured empty so they absorb |
| `Services/Ports/PortSession.cs` | `Stopped → Connecting → Connected \| Degraded` | same shape; `Stopped` deliberately does not accept `Faulted` |
| `Services/Transmission/BeaconQueue.cs` | `Queued → Sending → Sent \| Failed \| Expired \| Dropped` | same shape, four absorbing terminals |

The tables are stateless by design: `Fire(state, trigger)` builds the machine, fires and
returns the next state, because the caller already persists it. That is deliberate and
documented in each file.

The three adjacent non-machines are also deliberate and correct:

- `KeepAliveState` — a derived snapshot built through named factories
- `SessionLifecycleState` — an aggregate recomputed from the port set
  (`SessionCoordinator.UpdateAggregateStateLocked`, `:608-630`); it can legitimately
  jump between `Running` / `Degraded` / `Starting` as ports change, which is a
  function of the set, not a trigger sequence
- `AndroidLifecycleState` — mirrors what the OS reports; the platform owns the
  transitions

`AprsIsLoginStatus` and `PermissionGrantStatus` are value classifications with no
transition table, and are correctly not machines.

No change recommended.
